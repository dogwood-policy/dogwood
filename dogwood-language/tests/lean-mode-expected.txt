# The tests that fail when the whole suite runs with the Lean frontend
# (`DOGWOOD_FRONTEND=lean`, feature `lean-frontend`), and why: each reads a result
# that the Lean frontend gives in another form. `scripts/test-lean-mode.sh` runs the
# suite in Lean mode and fails unless exactly these tests fail. In `shadow` mode
# the whole suite passes.
#
# One test per line: the test binary's source, the test's name, the reason.
#
# Reasons:
#   cedar-wording    the test reads the text of Cedar's own diagnostics (Cedar's
#                    Rust validator's message for an error Cedar reports); Cedar's
#                    part of validation in Lean mode is cedar-lean's validator,
#                    which reports one error per rule, the first it finds, worded
#                    as Cedar words its kind but without all of Cedar's detail
#                    (an expected type, an attribute's access path, the action of
#                    a context)
#   cedar-span       the test reads the span of the subexpression Cedar's
#                    diagnostic labels; cedar-lean's findings carry no position,
#                    and the Lean frontend places them at their rule
#   temporal-span    the test reads the span of the offending node inside a
#                    temporal leaf; the Lean frontend places a temporal finding at
#                    its leaf (the specification form of the leaf, which its checks
#                    read, has no positions)
#   cedar-locations  the test reads the source locations of the lowered Cedar
#                    policies; the policies the Lean frontend's result is rebuilt
#                    into carry none
